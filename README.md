# 市场日历 · 微信小程序

模仿 Apple Calendar 的资本市场日历：**选定某一天，看这一天发生了什么**；**往前看三个月，看接下来要发生什么**。

索引精确到 `YYYY-MM-DD`，不做跨年份聚合。

---

## 一、功能

| 模块 | 内容 |
|---|---|
| **财经日历** | 选定某一天，按**时间顺序**列出这一天全球发布的经济数据、央行议息会议、央行动态与发布会——时间精确到分钟，一月 200+ 条 |
| 历史回顾 | 选定**某年某月某日**，只呈现这一天真正发生的：<br>(a) 已公布数据 —— **实际值 / 市场预期 / 前值 / 同比 / 环比**<br>(b) 大事件（突发 / 技术突破 / 政策 / 里程碑）<br>(c) 当日 A 股领涨领跌板块（真实行情） |
| 未来预告 | 未来 90 天的重要数据公布 + 技术发布会档期，带**倒计时**、**三档置信度**与**上期数值锚点** |
| **UP 主观点** | 每天抓取 B 站 UP 主「艾丽的无废话财经」的新视频，**下载音频 → 本地语音转写 → 提炼核心要点**，挂到视频发布当天的面板底部 |
| 我的笔记 | 在任何一天记录自己的想法，支持**标签**（复盘/计划/观察/灵感）、**搜索**、**云同步**；写过笔记的日子在日历上打蓝点 |
| 日历交互 | 月视图左右滑动切月、「今天」回位、日期打点（有内容灰点 / 预告黄点 / 笔记蓝点） |

### 财经日历（密度来源）

之前最大的问题是**用户最常看的那段窗口几乎是空的**——未来 60 天里 50% 的日子
打开是空白，平均每天不到 1 项。根因不是数据抓少了，而是**只有「数值」没有「日历」**：
数值源只覆盖重要指标，且美国数据源停在 2025-09。

现在接入东方财富完整财经日历 `RPT_CPH_FECALENDAR`，一天 20~40 条：

```
09:30  ▌CPI:环比        9 月   中国      低于预期
       ▌                              实际 -0.2% 预期 -0.1% 前值 0.7%
10:00  ▌美联储议息会议    华盛顿   事件
15:00  ▌泰国央行公布利率决议        动态
20:30  ▌核心CPI:同比      8 月   美国
```

三类内容缺一不可：

| 类型 | 内容 | 说明 |
|---|---|---|
| **经济数据** | 美国/中国/欧盟/日本/英国等 20+ 国的指标发布 | 每月 300+ 条，是密度的主体 |
| **事件** | 各国央行议息会议、国民经济运行情况发布会、中央全会、行业会议 | 每月 ~15 条，价值最高 |
| **动态** | 央行官员讲话、会议纪要、EIA 报告、CFTC 持仓、台积电月度营收 | 每月 60+ 条，东方财富 APP 里最实用的一类 |

**左侧色条表达重要度**（不写「★★★」文字——在密集列表里会变成视觉噪音）：
橙色 = 关键读数（CPI / 非农 / 利率决议 / M2 / 社融），蓝色 = 重要数据，灰色 = 参考信息。
默认「重点」视图只显示前两级，可一键切「全部」。

**数值与日历是两套数据源，按指标名对齐。** 东财日历只有排期没有数值，
所以当某个指标确实有真实数值时，会直接显示在那一行下方。
对齐表在 `build_dataset.py` 的 `CAL2MACRO`，构建时会校验并打印对不上的条目。

> **口径保守原则**：东财的「出口金额」只提供**累计同比**，而数据源里的出口是**当月同比**——
> 两者是不同的数（年初至今 vs 单月），所以**宁可不挂值也不混用**。
> 同理「累计」在归一化时不会被剥掉，只有「季调/非季调/当月/初值」这类纯口径修饰才会。

### UP 主观点（B 站视频自动总结）

选定某一天，面板底部会显示当天发布的视频要点，例如 2026-09-26：

```
UP 主观点 · 艾丽的无废话财经                      转写提炼
9.26 如果我是沃什…（二）
· 核心判断：若我是沃什，会推动 10 月美联储再次加息
· 通胀端：9 月国际原油价格较 8 月大涨，柴油价格进一步抬升
· 预期管理：10 月再加一次，市场对 12 月动作的猜测会更激烈…
                                在 B 站看原视频 ›
```

**为什么不能直接抓文字**——这三个环节我都实测过，都不通：

| 尝试 | 结果 |
|---|---|
| B 站 CC 字幕接口 | ✗ 该 UP 主的视频**没有上传字幕**（批量测 8 个，0 个字幕轨） |
| B 站自带 AI 摘要 | ✗ 需要登录态，返回 `-403` |
| 视频简介 | ✗ 全部为空 |
| **下载音频 + 本地语音转写** | ✓ **可行**（yt-dlp 取音频流 + faster-whisper） |

所以走的是「音频 → 转写 → 总结」这条路。抓取用 B 站**搜索接口**按 UP 主名过滤
（空间接口有 wbi 签名风控，需要登录 cookie，不可用）。

> **诚实说明**：要点由 AI 阅读**真实转写全文**后提炼，不是标题猜测，也不是编造。
> 语音转写会引入同音错别字（"原油"→"运游"、"劳动力市场"→"劳动历史场"），
> 总结时按上下文校正，但**如与原视频有出入，以原视频为准**——面板里保留了原视频链接。


### 我的笔记

在某一天有想法，点「＋ 写点想法」即可记录，写完自动归属到那一天。

- **本地优先**：写入立刻落 `storage`，断网、未配云环境都能用，绝不丢字。
- **云端静默同步**：配了云开发后自动双向同步，冲突按 `updatedAt` 后写胜出。
- **软删除墓碑**：删除会留墓碑，否则下次 pull 会把已删笔记又拉回来。
- **汇总页**：顶部「笔记」进入，按时间倒序，支持关键词搜索与标签筛选。

> **口径**：索引是**精确到日的 `YYYY-MM-DD`**，不做跨年份聚合。
> 选 2026 年 9 月 14 日，看到的就是 2026 年 9 月 14 日这一天的事——
> 不会混入 2025、2024 年同月同日的内容。没有收录的日子就明确显示「暂无收录」。

### 数值展示（核心）

每一天的数据事件都带一组真实数值，而不是一句"这一天发布了 CPI"：

```
2024-09-11   美国 CPI 月率           [符合预期]
实际 0.2%    市场预期 0.2%    前值 0.2%

2020-09-11   美国 CPI 月率           [高于预期]
实际 0.4%    市场预期 0.3%    前值 0.6%
```

- **实际 / 预期 / 前值**：来自财经日历口径，覆盖美国 CPI、核心 CPI、非农、失业率、ISM、GDP、PPI、零售销售、初请、PCE，以及中国 CPI、GDP、贸易帐。
- **同比 / 环比**：中国统计局口径数据（PMI、PPI、M2、社融、LPR）提供。
- **预期偏离**：用中性表述「高于预期 / 低于预期 / 符合预期」。刻意不判断利好利空——同一个"高于预期"对 CPI 和失业率方向完全相反，判断权交给使用者。颜色也刻意避开红绿，以免和板块涨跌混淆。
- **无公开预期的指标**（如 LPR）不摆空列，明确标注「官方数据 · 无公开预期」。

### 三档置信度（不把推算说成官宣）

| 标记 | 含义 | 例子 |
|---|---|---|
| **已官宣** | 官方已正式公布日期 | 美联储 FOMC 会议日程（federalreserve.gov） |
| **规律推算** | 按固定发布规律推算 | 非农＝每月第一个周五；LPR＝每月 20 日 |
| **待官宣** | 市场普遍预期，尚未官宣 | 各厂商秋季发布会档期 |

贸易帐、进出口、外汇储备、社融、LPR、统计局 PMI）。

> 一天最多可能发布 17 项数据（如 2008-02-01：美国非农 + 失业率 + ISM + 中国 CPI + PPI + M2…）。
> 界面用 **★ 重要度**分层：★★★ 高价值数据用暖色点亮，方便一眼定位。

> ⚠️ **数据边界（必须知道）**：当前公开数据源的**财经日历类数据（含预期值）更新到 2025-09**，
> 中国统计局口径数据（PMI / PPI / M2 / LPR / 社融）更新到 2026-09。
> 因此：
> - **历史回顾**（≤ 2025-09）：实际值 / 预期值 / 前值**三项齐全**，都是真实值。
> - **未来 90 天**：只给「上次实际公布值」作为锚点，本期预期显示 **待云端同步**。
>
> 云函数 `syncCalendar` 已接好金十数据中心接口，**数据源一更新就会自动填充本期预期**，
> 不需要改代码。也可以用有 Wind / Bloomberg 预期数据的账号把 `market_upcoming` 集合填满。

- 所有数据按**精确日期**归档，没有收录的日子明确显示「暂无收录」，不填充、不错位。

### 数据源时效性（决定「每日更新」能更新到什么）

| 数据 | 来源 | 数据源最新到 | 能否每日更新 |
|---|---|---|---|
| A 股板块行情 | 东财板块行情 | **实时** | ✅ 能 |
| 中国宏观（CPI/PPI/PMI/GDP） | 东财数据中心 | **2026-08 所属月** | ✅ 能 |
| 中国货币/社融/LPR | 统计局口径 | 2026-09 | ✅ 能 |
| 美国宏观数值 | 金十数据中心 | **2025-09** | ⚠️ 受限 |
| 本期市场预期 | 金十数据中心 | **2025-09** | ⚠️ 受限 |

> **必须知道的边界**：美国数据与「市场预期」的来源（金十经济日历）目前只更新到 2025-09，
> 滞后约一年。这不是代码问题——**换成别的数据源才能解决**。
> 中国数据已改用东财接口（数据源实时），因此中国部分可以真正每日更新。

| 部署云函数后 | 云端 18:05 更新 · 点此刷新 | 每天自动抓取，可手动刷新 |

| 数据 | 自动更新 | 说明 |
|---|---|---|
| A 股当日领涨/领跌板块 | ✅ | 云函数抓东方财富板块行情 |

### UP 主观点为什么不能走云函数

微信云函数内存上限 256MB，而 whisper 模型常驻约 1GB；总结环节还需要读语义的 AI。
所以这条链路只能跑在**本地**，用两个脚本：

```bash
# 一键更新（抓板块 + 抓 B 站并转写 + 抓宏观 + 重建数据包 + 重生成预览）
bash tools/daily_update.sh

# 查看哪些视频还没总结（附转写全文）
python3 tools/up_pending.py
```

流程是「**机器做抓取和转写，AI 做总结**」：

```
fetch_bilibili.py          搜索视频列表 → yt-dlp 下载音频 → whisper 转写
        ↓                  → tools/data/up_raw.json（转写全文，不入包）
   AI 阅读转写，写要点
        ↓                  → tools/data/up_summary.json（要点，入包）
build_dataset.py           按视频发布日挂到当天 → history.js 的 "u" 字段
```

`build_dataset.py` 末尾会打印「已转写但尚未总结」的清单，不会静默漏掉。

> **两阶段转写的必要性**：下载与转写放在同一进程会 OOM（实测 exit 137，
> 内存仅剩 70MB）。现在转写跑在独立子进程里，主进程先释放下载占用。

未配置云环境时完全离线运行，功能不受影响；云函数报错 / 断网均静默降级。


> **完整部署步骤见 [`DEPLOY.md`](DEPLOY.md)**（云环境、数据库集合、定时触发器、常见问题）。
>
> **想让手机在 Mac 关机时也能更新？见 [`云端部署指南.md`](云端部署指南.md)** ——
> 数据管线全部是纯标准库 Python，可以直接跑在 GitHub 上（免费、永久、Mac 无需开机）。

> iPhone 日历订阅 + 微信推送，**不需要注册、实名、审核、备案**。

```bash
open preview/index.html
```

手机外框 + 深色 Apple Calendar 观感。可点击日期、切换「历史回顾 / 未来预告」、
`←` `→` 切月、`T` 回到今天，底部「数据来源与更新说明」可展开。

### 2. 导入微信开发者工具

1. 打开微信开发者工具 → 导入项目 → 选择 `market-calendar/miniprogram`
2. AppID 选「测试号」或填自己的 AppID
3. 直接编译即可运行，**无需任何后端配置**

### 3. 重新生成数据

```bash
# 一键更新全部（推荐）
bash tools/daily_update.sh

# 或分步执行
cd tools
pip install akshare pandas yt-dlp faster-whisper   # 首次
python3 fetch_calendar.py    # 抓财经日历（东财，含未来排期与央行动态）
python3 fetch_macro.py       # 抓宏观数值：实际值/预期/前值/同比/环比
python3 fetch_sectors.py     # 抓板块行情（可选，已有基线数据）
python3 fetch_bilibili.py    # 抓 UP 主视频 + 音频转写
python3 up_pending.py        # 查看待总结的视频（附转写全文）
python3 build_dataset.py     # 合成数据包
python3 build_preview.py     # 重新生成预览版
```

**B 站视频的两个环境变量**（不设会失败）：

```bash
export HF_ENDPOINT=https://hf-mirror.com    # 国内拉 whisper 模型走镜像
export HF_HUB_DISABLE_XET=1                 # 不设会因 xet 传输 401 而下载失败
```

`MAX_NEW=6` 控制单次最多处理几个新视频（转写耗时约 30–60 秒/个）；
`WHISPER_MODEL=base` 可换成 `small` 提升识别质量，但内存翻倍（base 约 1GB）。

新增指标：在 `fetch_macro.py` 的 `INDICATORS` 加一行（attr_id + 指标键 + 名称 + 单位），
再在 `seed_upcoming.py` 的 `UPCOMING_RULES` 末位填上同一个指标键，未来日程就会自动带上数值锚点。
云函数里的 `JIN10_INDICATORS` 也保持同步，这样最新预期值才能下发。

### 4. 让 UP 主观点每天自动更新

`daily_update.sh` 负责抓取与转写，**总结这一步需要 AI**。可选两种方式：

- **手动**：跑完脚本后 `python3 up_pending.py`，把新视频要点写进 `tools/data/up_summary.json`，再跑一次 `build_dataset.py`
- **自动化**：用 WorkBuddy 的定时任务，每天固定时间执行「跑 `daily_update.sh` → 读待总结清单 → 写 `up_summary.json` → 重建数据包」

### 5. 启用云开发增量（可选）

1. 开通云开发，创建环境，把环境 ID 填进 `miniprogram/app.js`：
   ```js
   globalData: { cloudEnv: 'your-env-id', useCloud: true }
   ```
2. 右键 `cloudfunctions/syncCalendar` → 上传并部署（云端安装依赖）
3. 新建数据库集合 `market_sector`、`market_upcoming`、`market_notes`
4. 定时触发器已配置：每天 18:00（收盘后）自动跑
5. 同样方式部署 `cloudfunctions/notesSync`（笔记同步）

> 云函数用 Node 原生 `https` 抓取，**零第三方依赖**，部署更快、体积更小。
>
> **笔记的隐私边界**：`notesSync` 所有读写都绑定 `cloud.getWXContext().OPENID`，
> 用户只能访问自己的笔记；客户端传来的对象只取白名单字段，`_openid` 由服务端强制写入。
> 未配置云环境时笔记完全不离开本机。

## 五、几个实现上的关键决策

| 决策 | 原因 |
|---|---|
| 数据编译成 `.js` 模块而非 `.json` | 小程序不支持动态路径 `require`，必须静态导出 |
| 数值存紧凑数组 `[指标键,实际,预期,前值,同比,环比]` | 改成精确日期后数据点涨到 5600+，字典形式会把指标名重复存几千次，主包直接到 **2.1MB 超限**。抽成 `INDICATORS` 表后降到 **488KB**，主包 1.2MB |
| 数据用稀疏索引（只含有内容的日期） | 精确日期模式下 80% 的日子是空的，全量铺 365 天纯属浪费 |
| 板块剔除「昨日连板 / 融资融券 / MSCI」等 | 打板情绪、指数成分、资金标签类不是真板块，出现在「领涨」里会误导 |
| 板块列表接口做本地缓存 | 东财 `push2` 对高频请求会直接断连，缓存一次可离线复用 |
| 请求全局节流 0.18s + 指数退避 | 500 次并发抓取会触发 IP 级限流，退避后成功率显著回升 |
| 周频数据（EIA / 初请）只预告 6 周 | 91 天里 39 天都是周报会淹没真正重要的节点 |
| 云同步失败一律静默 | 云端是增强不是依赖，绝不让网络问题阻断看日历 |
| 日历订阅的 UID 用哈希而非序号 | 订阅日历靠 UID 识别日程，用序号的话每次刷新都会重复堆积 |
| `.ics` 时间统一用 UTC（Z 结尾） | 避开 VTIMEZONE 在各客户端的兼容差异；北京时间 -8 小时换算 |
| `.ics` 严格按 75 字节折行 | 中文一字 3 字节，不折行会被部分日历客户端拒绝解析 |
| 订阅源只收录 ★★ 以上 | 一个月两百多条会把手机日历塞满，反而看不见重点 |
| 数据抓取用「并集合并」而非整体覆盖 | 某个源当天抓失败（或换环境后没装 akshare）时，整体覆盖会把上次已有的指标一起抹掉。实测踩过：`cn_lpr` / `cn_shrong` 直接消失 |
| 数据管线保持零第三方依赖 | 除可选的 akshare 外全是标准库，这样能直接跑在 GitHub Actions 上，不需要本机开机 |
| 易变数据全部放云端，主包只做基线 | 上线后日常更新不必重新提审；只有历史事件库、B 站要点这类低频内容才需要重传 |
| 云端增量日历用「对象」而非「索引数组」 | 主包靠共享索引表省体积，云端增量不必同步整张表，直接用字符串更省事也更不易错 |
| B 站视频走「音频 → 转写」而非抓字幕 | 该 UP 主**没有 CC 字幕**（测 8 个视频 0 个字幕轨）、简介为空、B 站 AI 摘要接口需登录返回 `-403`——只有音频这条路通 |
| 转写跑独立子进程 | 下载与 whisper 同进程会 OOM（实测 exit 137，内存只剩 70MB）；拆开后主进程先释放下载占用 |
| 转写用 `base` 而非 `small` 模型 | `small` 质量略好但内存翻倍，同机并行下载时容易崩；`base` 对中文财经内容够用，实测 335 秒视频转写 62 秒 |
| 转写全文与要点**分开存** | 全文几万字/视频，入包会直接撑爆主包；要点 10 条约 600 字节，`up_raw.json` 只留本地存档 |
| 视频要点给「核心判断」而不是摘要 | 复盘的用途是看观点而非复述内容，所以每条都是可判断的结论（如「会推动 10 月加息」），不是「讲了美联储」 |
| 日历用「名称表 + 索引」而非直接存名字 | 同一指标每月重复出现，字典存会把名字重复几百次。抽成表后 7856 条只占 ~360KB |
| 日历条目存紧凑数组 `[时间,国家,名称,星级,类型,报告期,指标键]` | 与数值卡片共用指标表，避免同一天同一读数出现两遍 |
| 重要度用左侧色条而非「★★★」文字 | 密集列表里星级文字会变成视觉噪音，色条能让人眼快速扫出橙色关键行 |
| 「累计同比」不参与归一化 | 累计同比（年初至今）与当月同比（单月）是不同数字，混用会把读数挂错行 |
