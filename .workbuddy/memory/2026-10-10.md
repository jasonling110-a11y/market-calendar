## 🚨 本轮新坑：本机网络节点退化 → 「大请求体」被丢弃（**首次遇到，务必记下**）
- 现象：`push_via_api.py` 在第 1 个大文件就报
  `URLError: Broken pipe` / `RemoteDisconnected`；`git push`（含临时分支）报
  `error: unable to rewind rpc post data - try increasing http.postBuffer` +
  `SSL ... bad record mac`；`http.postBuffer` 调到 500MB 也无效。
- **实测阈值（curl 打 `/git/blobs`）**：
  - 16 / 64 / 256 KB 请求体 → 稳定 **201**
  - 512 KB（≈700KB JSON）→ **时好时坏，10 次里成功 5 次**
  - 1 MB / 2 MB → **基本全 000**（连接被丢）
  ⇒ 不是仓库/token/代码问题，是**上行被掐**；`--noproxy '*'`、走 `127.0.0.1:1082`
    两条路都一样。**唯一解法 = 重试**（大文件往往第 3～5 次能过）。
- **教训（我踩的坑）**：临时写的重试脚本一开始用
  `grep "✓ $f"` 判成功 —— 但 `push_via_api.py` 的 `[1/1] ✓ 文件` 是**blob 上传成功**就打，
  之后的**建 tree / 建 commit / PATCH ref 失败它照样打印这行** → 误判成 OK，
  导致 `docs/data/meta.js`、`docs/market-calendar.ics` 等明明没落地却被记成成功。
  **正确判据 = grep `推送成功`**（第 196 行那句，含 `main → xxxx`）。
- 收尾判据仍是**全量逐字节比对**（本次 103 个 tracked 文件）：先跑到 **2 个差异**
  （docs/app.html、preview/index.html），重试后 → **0 差异**。
- 线上验证：Pages `data/meta.js` → version=**202610102141**、up_days=**26** / up_videos=**30**；
  `app.html` 与本地 **sha256 完全一致**（`7807c473…`），4 个新 bvid 均可在线上页面检索到。
