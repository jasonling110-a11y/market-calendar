## 咨询：能否摆脱 WorkBuddy 定时任务、改成网页端自动抓取更新（未实施改造）

结论：**技术上可以**，需纠正一条长期误解 —— 此前记忆写的「Actions 没有 yt-dlp/whisper」
其实是「没装」，不是「装不了」。`tools/fetch_bilibili.py` 用的就是 pip 包
**yt-dlp + faster-whisper**，两者在 GitHub Actions（ubuntu-latest，约 4 vCPU / 16GB）上可安装可运行。

真正的唯一堵点是 **要点提炼需要 LLM 读语义** —— 目前由本机 AI 完成，无任何 API key 配置
（`tools/cloud_config.json` 只有云笔记的 applicationId/endpoint）。

三条路线（用户尚未选）：
1. 本机 launchd 定时（照 `设为开机自启.command` 再加一个 StartCalendarInterval 21:30 的 plist 跑 daily_update.sh）
   —— 只摆脱 WorkBuddy，仍依赖 Mac 开机，且要点提炼仍缺 AI。
2. **全上云（推荐）**：`daily.yml` 里 pip 装 yt-dlp + faster-whisper，新增 B 站抓取步骤；
   要点提炼改调 LLM API（DeepSeek，key 存 GitHub Secrets）。彻底不依赖 Mac 与 WorkBuddy。
   待验证风险：① B 站对数据中心 IP 的风控（可能 -352/403，需实测，必要时用 cookie Secret 且会过期）；
   ② CPU 转写 10 分钟音频约 2~5 分钟，加上模型下载，可能逼近 workflow 的 30 分钟 timeout（需调大或换更小模型）；
   ③ 公开仓库 Actions 分钟数免费。
3. 第三方 serverless —— **不推荐**：Cloudflare Workers 无持久进程跑不了 whisper；
   腾讯云 SCF / 阿里云 FC 能做但维护成本高于 Actions，无额外收益。

可复用资产：`summarize_up.py` 的零依赖抽取式兜底（已在 Actions 上跑）与其中的 `ASR_FIX` 同音错字表。

## 云端可行性探针：已实测完成（3 轮，结论明确）

新建了 `tools/probe_bili_cloud.py` + `.github/workflows/probe-bilibili.yml`
（workflow_dispatch 手动触发，只读不 commit）。三轮迭代结论：

| 环节 | 结果 | 说明 |
|---|---|---|
| 搜索接口（风控） | ✅ PASS | `search/type` code=0，命中 8~19 条 |
| whisper 转写 | ✅ PASS | 修复 `av` 版本后，模型加载 3.0s、转写正常 |
| **B 站下载音频** | ❌ **FAIL** | yt-dlp 与 API 两条通道**都 412** |

- 🐛 **踩坑 1（关键，已修）**：`av 19.0.1` 删除 `metadata_errors`，`faster-whisper 1.2.1` 仍传它
  → `open() got an unexpected keyword argument 'metadata_errors'`。
  **本机 av 18.1.0 正常**，所以现象是「本机能跑、CI 报错」，极易误判成 CI 不行。修法：`pip install "av<19"`。
- 🚧 **踩坑 2（真正的堵点）**：CI 的 Azure 数据中心 IP 被 B 站 412 全面拦截 ——
  不仅视频页，连 `api.bilibili.com/x/web-interface/view` 也 412；
  但 `search/type` 不 412（风控按接口分级）。本机住宅 IP **空 cookie 也能下** → 确认是 **IP 维度**。
- 🐛 踩坑 3：`push_via_api.py` 用 `git ls-files` 选文件 → **新建的未 tracked 文件不会被打包**。
  必须先 `git add -A` 再推，否则静默漏推（本次首推就漏了 workflow 与脚本）。
- 🐛 踩坑 4：workflow 里 `python ... | tee` 会吞掉退出码 → 步骤假「成功」。已加 `set -o pipefail`。
- 判定：**全上云需 SESSDATA 或住宅代理，不划算**；要摆脱 WorkBuddy 走本机 launchd。
- 探针脚本/workflow 保留在仓库，环境变化时可随时重跑（手动触发，不占定时额度）。
