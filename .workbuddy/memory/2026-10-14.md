## 🚨 重大发现：`git push` 其实可用（走 packfile，压缩后能过）
前几轮一直以为 `git push` 不可用、只能靠 `push_via_api.py`。本轮实测：
- `git push` 报 `non-fast-forward` 的**真实原因是本地与远端是两条平行历史**，不是网络。
- **解法**：先 `git fetch origin main:refs/remotes/origin/main` 拿到远端真 HEAD，
  再用 `git write-tree` + `git commit-tree <tree> -p <remote_head>` **把新提交挂在远端 HEAD 上**，
  于是变成 fast-forward，`git push origin "${c}:refs/heads/main"` **一次成功**（main → 284b9e4）。
- 关键点：packfile 是 zlib 压缩的，1.6MB 的 app.html 压完只有约 1/4，
  **恰好绕开了「>256KB 原始请求体被丢弃」的坑** → 比 `push_via_api.py` 逐 blob 重试稳得多。
- ⚠️ zsh 坑：`"$c:refs/heads/main"` 会被解析成参数修饰符 `:r`，必须写 `"${c}:refs/heads/main"`。
- ⚠️ `git fetch origin main` 只写 FETCH_HEAD，**不会更新 origin/main**；要显式 `origin main:refs/remotes/origin/main`。
- ℹ️ 远程 tracked 从 88 → 107（本地工作区文件比远端多，含 .workbuddy/memory、.genie 等）。
